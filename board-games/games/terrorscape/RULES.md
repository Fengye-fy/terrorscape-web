登录主站建房后，等待室可复制邀请链接。1–4 名真人可以同桌，房主点「补入人机并开局」时，服务器才把空席分给电脑。已有至少两名真人也可以「仅真人开局」。房主可在大厅房间列表或棋桌下方删除自己的房间，对局存档和邀请链接同时失效。

始终有三名幸存者及一名追猎者。2 人时一席控制三名幸存者；3 人时两席分别控制两名及一名；4 人时每名幸存者一席。默认最后一席控制屠夫；建房选项 `killerSeat: 'first'` 改由首席控制，`'last'` 保持末席；显式 `killerPlayerId` 始终优先。其他席按名单顺序循环分配三名幸存者。

幸存者同阵营共享位置和库存；追猎者看不到其当前位置、库存、当前回合尚未公布的普通噪音、无线电具体修复进度或物资牌序。屠夫位置、等级、力量、幸存者健康与恐惧、钥匙数、封锁及已经呼叫的救援倒数是公开信息。屠夫手牌内容、手牌数、牌库剩余数只对屠夫可见。

噪音不携带发出者身份。恐惧溢出产生的噪音立即公开；其他噪音在发现物资结束时整批公布。同房间最多一个噪音标记。下一轮幸存者开始时清除噪音。

旁观投影只含公开资料。游戏结束后可以回顾双方信息。所有动作均由引擎根据席位和阶段验证，不信任客户端提供的房间、物品、骰点或胜利结果。

## 幸存者流程

每轮按以下顺序进行：

1. 清除噪音；已呼叫的救援倒数减一；检查钥匙逃生及救援胜利。
2. 每名幸存者执行一次主行动，顺序可协商，由其所属席位提交。可在主行动前后使用额外行动和同房间交接物品。
3. 全部三名幸存者行动完毕后，团队选一名幸存者发现物资。
4. 公布本轮噪音，然后屠夫行动。

可执行的主行动：

- 移动相邻一步或连续两步；不能穿过被封锁的门。移动途中经过屠夫不会自动触发相遇，只有追猎者搜寻才会触发。
- 威廉还可选择冲刺主行动，最多移动三步，并在目的地制造噪音（依据规则书第 14 页的角色能力示例）。
- 休整：清除自己的全部恐惧，也可在没有恐惧时选择休整。
- 搜寻：在标有搜寻用途的地点抽一张搜寻牌，选择保留或丢弃；屠夫在同房间时不能搜寻。
- 修复：在起居室使无线电进度 +1，制造噪音；使用工具箱则 +2，约翰逊使用则 +3，消耗工具箱。屠夫在同房间时不能修复。**团队每轮仅可增加一次修复进度**，最高为 5。
- 拆除自己房间相邻门上的一个封锁；拆除信息立即公开。
- 特殊行动：急救包治疗同房间一名受伤幸存者，或以手电筒穿过密道；索菲娅无需手电筒即可使用数字场景密道。

发现物资时，从发现牌库抽两张、保留其中一张，其余丢弃；也可全部丢弃。牌库只剩一张时抽一张。抽出的任何带噪音图标物品都会在发现者房间产生噪音，保留与否均如此。搜寻牌同理。钥匙立即放入团队钥匙区，不占库存；其他物品加入背包。超过容量必须立即选择一件丢弃。

若进入发现步骤时牌库已空，并且还没有呼叫救援，幸存者失败；如果救援已在路上，则跳过抽牌并继续追猎回合。发现牌库只有两把钥匙，完整钥匙逃生路线需要搜寻物资。

## 恐惧、相遇及受伤

每名幸存者最多保留两点恐惧。受到第三次恐惧时维持两点，改为在其当前位置制造立即公开的噪音。每名幸存者有两点健康；第一次攻击失败受伤，再次受伤即淘汰，屠夫立即获胜。

屠夫在当前位置执行搜寻时，若同房间有人则发生相遇。移动本身不触发相遇。

相遇中，屠夫可以使用一张攻击技能，或直接发动攻击。幸存阵营从当前房间尚未被攻击的人物中选择一名防御者；只有拥有该人物的席位可以提交防御。防御者可使用一件防御物品，左轮手枪可额外配合弹药包。引擎掷 `4 - 恐惧数` 颗骰子，使用面值 `[0,0,1,1,1,3]`；加上物品和人物能力的防御，与屠夫当前力量比较。

- 防御大于或等于力量：成功抵挡；屠夫从牌库弃两张牌，并立即结束相遇。
- 防御不足：该人物受伤；如果尚有同房间未受攻击的人物，继续选择下一名防御者。每名人物在这次相遇最多防御一次。

相遇结束后，该房间每名幸存者可以选择留在原地，或沿一条未封锁的相邻路线撤离一步。撤离目的地对屠夫隐藏。随后屠夫抽三张牌，结束整个回合，不能继续普通行动或慢速技能。

## 屠夫流程及数字技能

屠夫从花园、等级 1、力量 5 开始，初始抽两张手牌。普通行动前可以使用任意数量快速技能；然后执行两次普通行动（每次移动一步或搜寻），或用一张特殊技能替代这两次行动；没有发生相遇时，普通行动后至多使用一张慢速技能。最后抽三张牌，手牌上限五张，溢出的新抽牌直接丢弃。

屠夫可以穿过被封锁的门，并同时移除该封锁。每次移动路线都公开给幸存者。可以提前结束屠夫回合。普通行动次数为零时，仍可选择合法慢速技能或结束回合。

以下为**数字场景的精简技能组，效果和数量并非实体屠夫牌组的逐卡复刻**：

|技能|时机|本场景效果|数量|
|---|---|---|---|
|感知 Sense|快速|选择红、蓝、绿一个区域，公开其中除安娜外的幸存者身份；不公开具体房间|2|
|追击 Pursue|快速|额外移动一步|3|
|惊吓|快速|当前房间幸存者恐惧 +1|1|

需要继续抽牌或从牌库弃牌时，若牌库已空，则将弃牌洗成新牌库并继续。屠夫随洗牌升至最高五级，各级基础力量依次为 5、6、6、7、7。首次升至三级时，屠夫额外获得「蛮力狂暴」，满手时自动弃掉最早的手牌腾位。技能的移动与追击依据[出版社的屠夫设计更新](https://terrorscape.backerkit.com/hosted_preorders/project_updates?page=5)适配到豪宅。

发现牌库为 24 张，其中钥匙 2、石灰粉 4、威士忌瓶 3、能量饮料 3、手电筒 2、急救包 3、古老护符 1、弹药包 2、左轮手枪 1、鞭炮 1、秘密地图 1、工具箱 1。搜寻牌库为 14 张，其中钥匙 5、工具箱 2，另有急救包、手电筒、石灰粉、弹药包、左轮手枪、威士忌瓶、秘密地图各 1；其中一把钥匙固定放在搜寻牌库底。所有数量都是本数字场景配置，不是实体 45 张物资的精确构成。

## 胜负与结束时机

- 幸存者：在幸存者回合开始时，团队至少有五把钥匙，且三人全部位于主厅；或者三人全部位于花园且有人携带秘密地图，即逃生获胜。只让一人抵达出口不够，动作途中不会提前检查。
- 幸存者：修复进度达到五立即公开呼叫救援，并设置倒数五。每次下一轮幸存者开始时减一；倒数到零时，只要还未有人被淘汰，团队获胜。不要求仍守在无线电房间。
- 屠夫：让任何一名幸存者第二次受伤被淘汰，立即获胜；或者在救援尚未呼叫时耗尽发现牌库、幸存者进入无牌可抽的发现步骤，获胜。

结束状态为 `phase: 'finished'`，结果为 `{ winningTeam, winnerIds, reason }`。双方整队算胜负，未实现 Separate Ways 的个人逃生、个人赢家与继续追猎。

## 插件和练习接口

同一份 UMD 文件同时支持 Node `module.exports` 和浏览器 `globalThis.TerrorscapeEngine`。服务端薄封装在本目录 `index.js`，公共实现位于 `apps/site/public/board-games/terrorscape/engine.js`。

公共函数：`manifest`、`validateOptions`、`validatePlayerCount`、`minPlayersForOptions`、`rulesetForOptions`、`getCatalog`、`createGame`、`applyAction`、`getView`、`getLegalActions`。

```js
const state = engine.createGame({
  players: [{ id: 'p1', name: '幸存者' }, { id: 'p2', name: '追猎者' }],
  options: { survivorIds: ['william', 'anna', 'marco'] },
  seed: 'local-practice-1', // 仅本地练习/测试；正式房间不使用公开种子
});
const view = engine.getView(state, 'p1');
const next = engine.applyAction(state, 'p1', view.legalActions[0]);
```

公开房间配置接受 `killerPlayerId`、`killerSeat`、`killerId` 和 `survivorIds`。其中 `killerId` 选择追猎者角色，`killerPlayerId` 指定操控该角色的玩家席位。旧存档可继续使用原阵容。`killerSeat` 仅可为 `'first'` 或 `'last'`，省略时与旧房间一致使用末席；规范化配置省略默认的 `'last'` 字段。显式 `killerPlayerId` 优先于席位位置。`options.seed` 会被拒绝。引擎内部随机状态与牌库不进入任何玩家投影。显式顶层 `seed` 可用于可复现本地测试；正式房间使用内部生成的随机种子。每次行动都复制状态，原状态不变；状态、动作、视图可 JSON 持久化。错误携带项目通用 `status` 和 `code`。

前端应展示并原样提交 `view.legalActions`，不自行假定所有相遇阶段都由幸存者行动。`encounter.stage === 'attack'` 时轮到追猎者，`defend` 时轮到幸存阵营；多席幸存者可以协商由谁先防御，各席只能提交自己人物的动作。

练习追猎 AI 应只读取追猎席视图与公开历史：根据已公布噪音、感知区域和前次相遇房间规划路径；到达怀疑地点时搜寻。不得读取服务器完整状态里的幸存者房间、物资或随机状态。普通移动不能自动显示或自动攻击躲藏的幸存者。

服务端 Node 插件额外导出 `chooseBotAction(view, legalActions = view.legalActions)`，只接受当前人机席位经过裁剪的视图与当前合法动作；返回该动作数组中的一个原始对象，无合法动作则返回 `null`。调用者每次执行后须重新读取该席位视图与合法动作，不能缓存旧动作。追猎者复用本地练习 `hunter.js`，随机取舍只依据自身可见资料生成。幸存者会协作修复无线电、搜寻钥匙、集合逃生或等待救援，并处理发现/库存取舍、治疗、恐惧、相遇防御、撤离及消耗道具。路线遵守封锁和角色密道权限；优先修复与治疗，救援期间分散避开追猎者。人机不执行可反复撤销的免费物品交接，避免多席人机来回交还物品形成循环。该策略是有限信息启发式对手，不保证最佳策略或胜率。

## 中文卡牌与操作提示

棋桌提供持续可见的中文手牌/背包区、发现/搜寻抽牌区和屠夫升级面板。点卡牌可查看本场景效果、使用时机及当前服务器允许的操作；幸存者小队可切换人物查看各自库存。卡面将抽到产生噪音与使用产生噪音分开标注，额外行动明确不占主行动。最近入手提示仅比较本页收到的可见库存，不是完整抽牌历史，刷新后不保留。

选角时展开追猎者的牌组可查看每种起始牌的张数、效果、使用时机及各等级能力。幸存者席显示起始物品。对局中的升级面板标出当前等级。追猎者可以点「牌库剩余」按牌名查看尚在抽牌堆里的牌，悬停在手牌上可查看同名牌的剩余张数。牌序对所有人隐藏，实时数量仅追猎者席及终局回顾可见。
